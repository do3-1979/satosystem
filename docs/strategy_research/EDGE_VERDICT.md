## 判定: ❌ 現状構成は「棄却（KILL as-is）」 / 条件付きで限定的価値

**本番構成（RiskOverlay ON + RangeBreakoutEnhanced ON）を全期間連続で回すと −108 USD の負け。**
2つの構成バグを外した最良構成でも +2,683 USD だが、**その利益は実質2024年単年（+1,770）に集中**し、

## ★★最重要バグ: ストップ約定が4H終値で行われる★★（ユーザー指摘により発見）

### 症状
- ストップ発動の**判定**は4H足の intrabar 安値/高値で行う（`low_price <= stop_price`, trading_strategy.py:1432）。
- 現実的な約定価格 `stop_price*0.995` を `trade_decision["exec_price"]` に計算するが、**この値はどこからも
  読まれず死んでいる**（`execution_delay_candles` と同じ）。
- 実際の約定は bot.py:443-446 で `price = get_ticker()` = **4H終値**で行われる。
- つまり「ストップに触れたバー」を**終値**で決済 → 下ヒゲでストップに触れて終値が回復した場合、
  **回復後の終値**で決済し、実際には取れないリターンを計上する（本番は60秒毎チェックでstop値約定）。

### 影響（BTC本番config, ストップをstop値約定に修正して比較）

| 期間 | 現行(4H終値約定) | **現実(stop値約定)** |
|---|---|---|
| 2024(強気年) | +2,695 / 勝率87.5% / DD0.1% | **+26 / 勝率70% / DD58%** |
| 2024-2026連続 | +3,026 / 勝率95% / DD39% | **−15 / 勝率83% / DD70%** |
| 2023(OOS) | −156 | −177 |

- **ヘッドライン利益+3,026はほぼ全てこのバグの産物**。stop値約定にすると強気年ですら+26に激減、
  全期間で−15の負け、DDは39%→70%に爆発。勝率95%の非現実さもこれで説明（回復終値で決済→勝ち水増し）。
- PSARトレイリング自体は正常動作（唯一のexit・トレンドを捕捉：例 55.7k→65.1k保持）。問題はPSARではなく**約定処理**。

### 是正
- EXIT時、`trade_decision["exec_price"]`（stop±slippage）が存在すればそれで約定させる（bot.py:443-446）。
- これは実装バグの是正であり、旧戦略の**真の期待値はマイナス**であることを確定させる。
- 注: 新CTAプロトタイプはストップ不使用（連続リバランス）のため本バグの影響を受けない。

- 単独収益エンジンとしての再開は依然非推奨。**次段の必須改善＝レジーム/上位トレンドフィルタで
  チョップ相場（2023,2026）の損失を除外できるかを、過剰最適化を避けた最小パラメータで検証**。
- 採用するなら: 2バグ修正＋保守的サイジング＋単純なトレンドフィルタを、全OOS窓プラス＆現実コスト＆
  生存可能DD（<40%目安）で満たした場合のみ、縮小サイズで限定運用。

## 最終結論
- **現状本番（−108・不稼働）は是正必須**。2バグ修正＋保守的サイジング(`config_fixed_consv.ini`)で
  「生存可能な薄い黒字」(現実コスト+884, DD55%)へ改善でき、現状を厳密に上回る（no-regret）。
- ただし **長期・全天候の頑健なエッジは存在しない**: 利益は2024強気相場依存、直近2026は損失、
  エントリーフィルタでは修正不可。**設定変更だけで「長期的に利益が出る」状態には到達できない。**
- 真の長期収益化には、トレンドフォロー単独依存からの脱却（別アノマリー/分散/別時間軸/上位足レジーム
  ベースの稼働制御など、エントリーフィルタではない構造的変更）が必要 → 別途設計フェーズ（要再依頼）。
