# LIVE GROUNDTRUTH — 本番BOTの実測検証（Phase 0）

作成日: 2026-07-01
検証元: Raspberry Pi 本番機（`ssh raspberry_pi`, commit `fff59b3`, gen2）、ライブログ実測
検証者環境: WSL2開発機（本番に影響なし・読み取りのみ）

---

## 結論（最重要）

**本番BOTは「損をしている」のではなく、「3.5ヶ月以上、一度も取引していない」。**
2026-03-20〜2026-07-01 の全104アーカイブログを走査し、**注文約定はBTC/XAUTともゼロ件**。
`total_pnl=0`, `position=NONE`。「全く利益が出ない」の正体は **完全な不稼働（取引不発）**。

さらに、**同期間をバックテストすると本来5回取引し −153 USD の損失**。つまり問題は二重：
1. ライブはバックテストが取るはずの取引を取れていない（シグナル/執行の乖離）。
2. 仮に取れていても、足元のレジームでは戦略自体が負ける（過去の+3,062 USDは旧期間・主に2024Q4依存）。

## 2. なぜ取引が発生しないか（実測根拠）

- ライブログ唯一の「不足」メッセージ＝ **`[Range Breakout Enhanced] ✗ 出来高不足`**（BTC 126件 / XAUT 293件）。
- RangeBreakoutEnhanced の相対出来高フィルタ（1.5×）に到達したブレイク候補が **100%却下（合格0件）**。
- ブレイク強度・相対出来高は **リアルタイムの `get_ticker()` とBybitライブ出来高** で評価される。
  バー確定後にBOTがポーリングする時点では価格/出来高がブレイク水準から離れており却下されやすい
  （＝バックテストの「バー終値＝ブレイク値」前提との乖離）。RATE LIMITによるデータ欠落も増幅要因。

## 3. ライブ vs バックテスト（同一ウィンドウ 2026-03-20〜06-28, 同一config）

- **乖離①（執行）**: ライブはBTで取るべき5取引を1件も取れていない。
- **乖離②（エッジ）**: そのバックテスト自体が −153 USD の負け。直近レジームでは戦略が機能していない。

## 4. 既存「+3,062 USD」の正体（再掲・別資料と整合）

- 利益の大半が **2024Q4（BTC強気相場, +1,748 USD ≒ 全体の57%）** に集中。
- 取引数は2年強で約33件＝統計的有意性に乏しい。直近2026は横ばい〜負け。
- 50以上の可変パラメータを8四半期に適合＝過剰最適化。walk-forwardで5窓中3窓が劣化率<-100%。

## 推測→実測で確定したこと / 残る未確定

- 確定: ライブは不稼働（0取引）。残高は十分。出来高フィルタが全ブレイクを却下。直近backtestは負け。
- 未確定（Phase 1で特定）: 出来高フィルタがライブで全却下する正確な機構（リアルタイム価格/出来高の
  取得タイミング・RATE LIMIT欠落・相対出来高lookbackの挙動）。エージェント推測の「スリッページ5〜25倍」
  「20〜30%誤約定」は**実約定が0のため検証不能**＝現時点では棄却（取引していないのでスリッページは無関係）。
